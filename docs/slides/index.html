Every suggestion on the Menstrual day is really two claims, and each one needs a source. First: does this nutrient help in this phase? My coding agent searched Cochrane, the NHS, EFSA and PubMed, and I went through what it found. Iron is Strong, vitamin C and magnesium are Moderate. Every source and quote is in EVIDENCE.md. Second: does this food actually contain the nutrient? That's the part I checked myself. The agent took the iron and vitamin C values from USDA's food database, and I checked five of those ten by hand on the USDA website. The five magnesium values I looked up myself. All 15 values are written into the tests. If anyone changes one, a test fails. This is only true for the Menstrual phase. The other phases are still example foods, and the tool says so.

Passing tests didn't mean the code was right

✓ All tests passed

30 Nov · autumn

Fiber: oats

Same cycle: one day pears, the next day oats

  • My rule: one food for the whole cycle
  • Found by checking the code against my spec, in my code review

Review 2, finding b3 · fixed in commit b001977

All my tests passed. But in my code review, I compared the code with my spec. My rule was: once the tool picks a food for a nutrient, you keep it for the whole cycle. In a test run, the same cycle gave pears on the 30th of November and oats on the 1st of December. Overnight, autumn turned into winter, and the tool picked again instead of keeping the food it had saved. No test ran the same cycle across a change of season, so everything was green. I fixed it: a re-run now keeps the saved food. And I added a test that fails on the old code. What I learned: passing tests only check the cases you thought of. The spec is what tells you if the code is right.
